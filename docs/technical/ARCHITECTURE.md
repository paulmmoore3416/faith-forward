# Architecture

Faith Forward is a static, multi-page web application built with **Vite + TypeScript + Tailwind CSS v4** and deployed to **GitHub Pages**. There is no server. Dynamic features run in the browser, persist to `localStorage`, and can optionally use **Firebase** (Firestore + Authentication) through its REST API.

```
┌────────────────────────── GitHub Pages (static) ──────────────────────────┐
│  Public site            K9 Handler Training Suite      Command Center     │
│  index, about, …        k9-suite.html                  command-center.html│
│        │                       │                              │           │
│  src/pages/*.ts          src/k9/*.ts                    src/cc/*.ts        │
│        └──────── src/layout.ts · src/config.ts · src/data/* ──────┘        │
│                                                                           │
│  public/content/  ← generated by scripts/content/*.py                     │
│     articles/*.md + index.json   social/posts.json + posts.csv            │
└───────────────────────────────────────────────────────────────────────────┘
           │ optional (REST, no SDK)               │ optional (OAuth in browser)
           ▼                                       ▼
   Firebase: Firestore + Auth             Google: Gmail · Drive · Calendar
   (form submissions, staff sign-in)      ElevenLabs: text-to-speech
```

## Directory map

| Path | Purpose |
|---|---|
| `*.html` | One file per page. Every top-level `.html` is picked up automatically by `vite.config.ts`. |
| `src/config.ts` | **Single source of truth** for organization details (names, founder titles, mission, contact, donation needs, 501(c)(3) status). |
| `src/firebase.config.ts` | Firebase web config (public identifiers only). Empty = forms fall back to email. |
| `src/layout.ts` | Shared header, crisis bar, footer, mobile nav, `esc()` HTML escaping. Imported by every page script. |
| `src/input.css` | Tailwind theme (brand colors sampled from the crest) and component classes in `@layer components`. |
| `src/data/devotional.ts` | Daily devotional engine: 106 KJV verses, 70 quotes and 71 original prayers, plus fixed and moveable feasts (Easter computed). |
| `src/data/events.ts` | Public events list. |
| `src/data.ts`, `src/resources.ts` | St. Louis veteran resource directory (from STL Veterans Hub). |
| `src/pages/*.ts` | Page scripts (home, donate, events, news, basic). |
| `src/lib/submit.ts` | Form handler: Firestore REST write when configured, `mailto:` fallback, honeypot spam field. |
| `src/k9/breeds.ts` | Breed library: 4 pit bull family breeds, GSD, Malinois, Labrador. |
| `src/k9/curriculum.ts` | 8 programs, 76 lessons, with gating rules for protection work. |
| `src/k9/care.ts` | Nutrition math, vaccines, preventives, first aid, exercise plan generator, routines. |
| `src/k9/store.ts` | K9 suite persistence (`localStorage` key `ff-k9-suite-v1`), CSV/JSON export. |
| `src/k9/app.ts` | K9 suite UI (hash-routed tabs). |
| `src/cc/app.ts` | Command center UI (hash-routed views, `localStorage` key `ff-cc-v1`). |
| `src/cc/firebase.ts` | Firebase Auth (email/password) + Firestore reads via REST. |
| `src/cc/google.ts` | Google Identity Services OAuth token flow for Gmail/Drive/Calendar (read-only scopes). |
| `scripts/content/` | Python generators for the 52 articles and 546 social posts. |
| `public/content/` | Generated content served as static files. |
| `firestore.rules` | Security rules: public create-only submissions, staff-only reads. |
| `.github/workflows/deploy.yml` | Build and deploy to GitHub Pages on push, manually, and daily (so scheduled articles go live). |

## Key design decisions

1. **Static hosting, no server.** Free, always on, nothing to patch. Anything needing a secret runs either on the user's own device (Settings) or in Firebase behind security rules.
2. **No secrets in the repository.** The repository is public. See [SECURITY.md](SECURITY.md).
3. **Local-first data.** The K9 suite and command center work fully offline in one browser, with JSON export/import for backups. Firebase sync is optional.
4. **Content as data.** Breed data, curriculum, devotionals, events, and marketing content are typed data files, not hard-coded markup, so non-developers can edit them safely.
5. **Scheduled publishing without a server.** Articles carry a publish date; the News page only shows articles whose date has passed, and the daily workflow run rebuilds the site.
6. **Accessibility.** Semantic landmarks, labeled form controls, sufficient contrast on the navy/gold palette, `prefers-reduced-motion` respected, print stylesheets for reports.

## Data stores (browser)

| Key | Owner | Contents |
|---|---|---|
| `ff-k9-suite-v1` | K9 suite | Dogs, lesson progress, logs, medical records, handler certifications |
| `ff-cc-v1` | Command center | Tasks, donations, outreach contacts, people, posting status, on-device settings (API keys) |
| `ff-cc-unlocked` (sessionStorage) | Command center | Local-mode unlock flag for this tab |
| `ff-cc-fb-session` (sessionStorage) | Command center | Firebase ID token (expires after ~1 hour) |

The command center reads `ff-k9-suite-v1` (same origin) to show the K9 summary.
